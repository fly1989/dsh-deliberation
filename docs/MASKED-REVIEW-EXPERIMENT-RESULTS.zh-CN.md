# Masked Review 探索性配对实验：结果、发现与避坑记录

日期：2026-11-18。本文是 2026-11-07 至 11-17 这一轮本地实验的收尾记录。它不是效果声明，也不改变插件的默认行为。研究假设本身见 [MASKED-REVIEW-RESEARCH-NOTES.zh-CN.md](MASKED-REVIEW-RESEARCH-NOTES.zh-CN.md)。

> **当前结论**：本轮未观察到隐藏 reasoning 带来稳定的独特收益，也出现过有害反馈，因此结束这一轮效果验证。样本和对照覆盖有限，不能据此判断所有 masking 方案普遍有效或无效。仓库继续维护，实验收尾不构成对插件全部能力的效果结论。

文中的标签沿用研究主文档：**本地观察**是本轮实际看到的行为，不能外推；**研究假设**是尚未被验证的主张。

## 1. 测了什么

本轮主要的保留／隐藏配对，从真实 Primary 轨迹构造合成 user 文档，交给 review child：保留组在文档里附上已记录的 reasoning（`retain-reasoning`），隐藏组省略它（`reasoning-only`）。每一对内的系统提示、任务、输出协议、工具权限和模型配置匹配；实际读取路径可以不同。不同批次的提示和模型路由不完全相同，不能把它们当作同一大样本合计。

| 记录 | 题目与断点 | 对照 | 本地观察 |
| --- | --- | --- | --- |

| E2 | AnyIO 取消竞态，Step 47：已经复现、尚未改源码 | 三组：不审查、保留、隐藏，各 1 次；另做对第 6 条的消融 | 不审查组 62/62（三次尝试里唯一留下补丁的一次），保留组 62/62，隐藏组 58/62 |

有可复现闭环验收的主要记录来自**两道题**；其他导入轨迹和静态 PR 仅能回答各自条件下的问题。同一题的重复运行不算独立样本。这是一轮探索性研究，不是大规模 benchmark。

E2 的不审查臂三次尝试仅一次留有最终补丁，且以传输错误结束。原七条隐藏 packet 的初次续跑和一次更换提案说明后的复测均为 58/62。删除整条第 6 项后，一次补丁达到 62/62，但最终请求仍传输失败。这支持该条提案影响修法，具体是哪句起作用、是否存在采样差异仍不确定。

## 2. 发现

### 2.1 E1：已考虑的候选出现了不同的发布决定

**本地观察**。E1 中，“body 不该带顶层头”是唯一指向真实失败的疑点。逐句阅读 child 的 recorded reasoning 后发现：

- 4 个 child **全都考虑过**这个疑点，只有 1 个隐藏组 child 把它作为 uncertain 发布了。
- 两个保留组 child 不发布的理由是：题面字面上支持完整 MIME、模型记得上游实现就是这样、给不出可行的检查，再加上提示规则带来的克制。其中一个自评 “~75% full is right. So no.”
- 两个保留组 child 都**没有**把“Primary 已经讨论过”当作理由，反而说 actor “did not question”。

E2b 的 changelog 也类似：保留组也有一个 child 想到了，但以“用户没要求”为由否决。

因此，“隐藏组发布了、保留组没发布”不能写成“隐藏组发现了保留组想不到的东西”。另外需要提醒：reasoning 里没有出现，也不等于模型想不到；reasoning 里出现一句正确的猜测，也不等于模型有能力把正确方案做出来。

### 2.2 两道题中观察到的裁决与验证问题

**本地观察**（两道题，样本很小）：

- **争议点靠推理或记忆拍板。** E1 的契约有歧义，当时提供和实际取得的材料没有给出足以裁决的 fixture 或调用方证据。Primary 在原轨迹和 6 次带反馈的续跑中，仍按推理选择完整 MIME，并将检查结果总结为已确认。
- **检查执行了，判准却沿用了待验证的假设。** 续跑自测只证明实现与某种完整 MIME 构造一致。免费交叉检查发现：它在错误实现上通过，在正确实现上反而报错。两种实现确有不同输出，但这个判准不能正确裁决目标契约，形成了错误的安心感。
- **未经检验的排他断言被当成定论。** E1 中，Primary 用一句没验证过的解释（“should match. Not issue.”）排除了一个反常结果。E2 中，隐藏组断言“在 release 里提前清理必然破坏旧测试”，事后被反例推翻；Primary 采用的修法解决了挂起，却遗漏 release 后即时 waiting 统计，仍为 58/62。错误的是无依据地排除可行修法，取消清理时移交本身并非必然错误。

这些关键决策说明，候选已经出现仍可能在裁决与落实上失败。仅两道题不足以排序 Agent 的普遍瓶颈。“怎样让备选解释获得可靠裁决，以及无法判定时怎么办”是可以保留的研究问题，不是已验证的解决方案。

### 2.3 一条清楚的取证链条

**本地观察**。E2b 中，一个隐藏组 child 起初也认为 changelog “Not decision-critical”。随后它去读了 Primary 从没读过的 `AGENTS.md`，拿到了明确的仓库要求，于是发布；Primary 续跑时又自己核对了一遍并补上。

链条是：已有候选 → 读取此前没看过的文件 → 依据变得更可靠 → 实际交付。

这只有一次，不能说明它是 mask 带来的；同一组的另一个 child 没有读任何文件、只凭“仓库惯例”也提了 changelog。两条隐藏反馈续跑都交付了 changelog，两条保留反馈没有，但只有一次由新增读取支持。它展示了取得更可靠依据后改变决策的具体链条；不能推导“多读文件”普遍有效，E1 当时就未取得同类裁决依据。

### 2.4 新颖性过滤可能与输入表示相互作用

**实现事实**：

- 保留组的 reasoning 被渲染在 `Assistant visible content:` 标签**之下**；隐藏组没有任何“此处已省略”的标记。
- 审查提示写着：复述 “a visible Primary conclusion” 不算 delta，并要求先和 “Primary-visible history” 比较。

两组判断“已知内容”时可见材料不同，同一疑点可能被归为重复或新增。提示也允许 uncertain、contradiction、不同路径与具体检查，不能描述成“拿不准就禁止发布”；仍值得澄清的是，“以前出现过”不等于“已经被证据解决”。日志中能看到 child 在这些类别之间犹豫。

这是一项有记录支持的候选解释，不是已经隔离出的原因。E1 的保留组也反复依据题面与上游记忆选择完整 MIME，没有直接说“Primary 已讨论过所以不报”。没有做过改规则的对照，不能断言改提示能替代 mask。

### 2.5 其他值得记住的观察

- **certainty 自报不可靠**：E2 的一条错误结论被标成了 certain。
- **正确考虑过也不保证最终反馈正确**：E2 隐藏 child 自己的 reasoning 写过 Semaphore 没有所有权限制，最终 packet 却仍将其与 Lock 的所有权错误一起否定。不能仅以删除原解释造成信息缺失来归因。
- **有害反馈是真实存在的**，不能宣传“最坏也没有负收益”。
- **update 数量不等于召回**，条目数量也不等于发现数量：E2b 中一个 7 条的 packet，大部分是复述。
- **只看 packet 会误判**：child 的 recorded reasoning 是关键的分析材料。

## 3. 避坑清单

### 3.1 评测隔离

- E4 中，Primary 的 bash 能访问实验仓库的根目录，读到了写着修法和隐藏验收测试名的冻结案例文档，以及 runner 正在写入的 results.json。这段工具输出又进入了两组 reviewer 的输入。
- 给 child 的读取工具加路径限制，修不好已经进入父历史的污染。
- 运行前要用 Primary **和** child 的实际工具各做一次路径探针，确认读不到参考修复、隐藏测试、评测日志和其他运行的结果。

### 3.2 样本

- 已经通过选定验收的候选很难用同一套测试观察纠错收益。E3 在自然收尾前已通过，E2b 在预算耗尽时已通过。GPX 只提供已解决标签和可见轨迹，没有本轮续跑验收。
- 预算耗尽时停下 ≠ 自然停止 ≠ “基于错误判断改坏了代码”的中途断点。
- 本轮最后一次限额筛选，目标限定为错误判断已经导致产品代码走偏、且中途状态可恢复的断点。本地只有 8 条已选轨迹，5 条已分析而排除，其余 3 条未找到符合条件的断点；实际约 15 分钟后停止，没有生成新 Primary、恢复代码、运行验收或调用 reviewer。清单中的 223 条只是历史初筛计数，不是本地现存的 223 份可复现样本。
- “未取得样本”不是新一次 mask 无效的结果。上述筛选条件也比一般的错误取证、验证或结论更窄，不能写成所有 Agent 探索研究的必要条件。
- **找样本和采集 Primary 轨迹**往往才是主要成本，预算必须把它算进去。
- 本轮 update／no_update 不同的配对都来自同一道需求有歧义的 multipart 题；这不表示其他样本的具体内容完全相同，也不足以外推。

### 3.3 设计与统计

- 运行前记录真值说明、匹配规则和提示的版本与 hash。事后更正应保留原始结果与更正原因，不能把参与调参的数据再称为独立验证；也不能把 hash 不变误认为真值必然正确。
- 对称统计：隐藏独有、保留独有、共同候选、错误候选都要统计，并写明核实依据。不要只找隐藏组赢的那一条。
- 区分“重新解释已有信息”和“读到了新信息”。
- 判断 child 的输出时，不要以修好率作为唯一指标；还要看依据是否更可靠，以及是否支持了后续选择。正确地保留原方案、避免一次错误修改，也算收益。
- 不要用旧样本调提示，再把结果当作独立验证。

### 3.4 本轮未覆盖的部分

- 所有效果实验里，更早的已完成 Turn（H）都是空的，窗口一律是 `current-turn`。非空 H 和 `recent-steps`（K）都没有被测过。
- 两组都用合成文档；“原生历史回放 vs 改写后的执行记录”从来没有对照过。
- 实验 runner 用的是最小 kernel，不是完整的 Web profile。

### 3.5 容易说过头的地方

- 模型自评的“75% 把握”不是采样概率；reasoning 里最后选了一个解释，也不等于解码器“杀掉了概率尾巴”。
- RL 让探索变窄是一个有证据的现象，但不是通则；不能借此反推某个模型具体被压住了什么能力。
- 本轮使用的 DeepSeek thinking 接口忽略 `temperature`，不能把调整它当成本轮的多样性控制。

## 4. 当前状态

- 本仓库继续维护插件实现、兼容性说明、使用文档与研究记录。
- 运行时、child 启动、结构化反馈和 Primary 续跑都已经实际运行过。
- mask 效果线就此收尾：没有观察到稳定收益，有过负收益，有一组被污染。
- 自动审查继续默认关闭；masked-review 保持实验定位。
- 暂缓 reasoning 长度分布、动态切点和熵触发的研究。
- 如果以后继续，建议的问题是：在同一前缀下，少量额外探索能否获得更可靠的依据，并支持更好的下一步选择？mask、反事实提示、换模型都可以作为探索手段，但不要事先认定哪一种有效。
- 当前没有启动新的实验。后续若开展研究，应独立声明问题、样本范围、预算和判断标准，公开有差异、无差异及负面结果；不把本轮的未覆盖设想写成既定优势。

## 5. 不能据此下的结论

- “mask 无效”或“mask 有效”；
- “保留组想不到某个问题”；
- “改提示词就能替代 mask”；
- “问题都出在模型本身”；
- 稳定的总体成本、延迟或缓存优势。

## 6. 材料位置

实验 runner 与相应适配主要位于本地的 `experiment/*` 分支，不代表已合入 `main` 或发布到 npm。原始 session、补丁和验收日志保存在被忽略的本地 `.cache/` 目录，不随仓库发布；本文汇总了这些记录及后续复核，也区分了观察与归因。

目前公开的是收尾摘要，未发布完整轨迹和可独立重跑的评测包。读者不能仅凭本文重算全部结果，因此不应将它当作可公开复现的大规模 benchmark 或效果认证。
